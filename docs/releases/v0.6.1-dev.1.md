# PocketShelf 0.6.1 development/test build

**This is a development/test pre-release, not a production release.** It is intended for manual testing on supported New Nintendo 3DS-family hardware. It must not be treated as hardware-validated or production-ready.

The GitHub pre-release body records the exact merged `main` commit and SHA-256 hashes for every clean release build. `SHA256SUMS.txt` is published beside the test artifacts so downloaded files can be checked independently.

## Installation

### Homebrew Launcher

1. Download `pocketshelf.3dsx` and `pocketshelf.smdh` from the same pre-release.
2. Verify both files against `SHA256SUMS.txt`.
3. Place them in the PocketShelf application directory used by the Homebrew Launcher on the SD card.
4. Launch PocketShelf through the Homebrew Launcher.

### CIA development/test package

1. Download `pocketshelf.cia` from the same pre-release.
2. Verify it against `SHA256SUMS.txt`.
3. Install it with a trusted CIA installer on a console configured to install homebrew software.
4. Treat overwriting an existing title as destructive and keep recoverable backups first.

Install only software you trust and are legally entitled to use. The CIA changes Home Menu title storage.

## Security warning: trusted-LAN HTTP only

PocketShelf currently connects to RomM with plain `http://`. The RomM bearer token is sent unencrypted on authenticated requests and stored unencrypted in `sdmc:/3ds/PocketShelf/settings.ini`. Use this build only on a trusted, isolated LAN. A hostile network peer could steal the token or replace downloads.

Production updater trust remains intentionally disabled in `source/release_config.cpp`: there is no configured release origin, key ID, or Ed25519 public key. This pre-release does not enable self-update trust and is not an updater-compatible production release.

## Current limitations

- Targets New Nintendo 3DS-family systems; older models are not the current target.
- Designed for RomM 5.4.
- RomM connections use trusted-LAN HTTP rather than HTTPS.
- Hardware behavior must be validated separately from host tests and package verification.
- Save download places backups into Checkpoint-compatible or PocketShelf-managed backup locations; it does not restore directly into live game save archives.
- CIA installation and overwrite operations modify title storage and require explicit care.
- Automatic production updates remain unavailable and fail closed while release trust is disabled.

No physical-testing claim applies to a newly rebuilt release unless results are explicitly recorded for its exact commit and hashes.

- [ ] Launch the `.3dsx` build on a supported New Nintendo 3DS-family console.
- [ ] Install and launch the `.cia` build on a supported console.
- [ ] Confirm first-run settings creation and persistence.
- [ ] Connect to RomM 5.4 on an isolated trusted LAN with a test token.
- [ ] Exercise authenticated catalogue pagination, search, filters, sorting, covers, and screenshots.
- [ ] Test supported downloads, cancellation, interruption, low-space handling, and partial-file cleanup.
- [ ] Test CIA new installation, cancellation, and explicit overwrite confirmation with recoverable test content.
- [ ] Test Checkpoint title binding plus managed-save fallback upload/download flows with disposable backups.
- [ ] Exercise sleep, Home Menu transitions, reconnect, and application exit.

- [ ] Record console model, system version, RomM version, exact release commit, artifact hashes, and observed failures.
